# Супер-админ команден център — дизайн

**Дата:** 2026-07-25
**Статус:** одобрен дизайн, чака имплементация
**Свързано:** съществуващ `/admin` (requireAdmin, admin.ts actions/queries), [[transaction-fee-monetization]]

## Проблем / цел

Потребителят иска пълна видимост „всичко случващо се с проекта" през супер-админ акаунт
(`supportfrizmo@gmail.com`). Съществуващият `/admin` вече покрива: платформени метрики
(магазини/публикувани/поръчки/оборот/търговци), списък магазини (търсене/филтри/блокиране)
и проблемни inv.bg фактури (retry/annul). Липсва: монетизационен изглед (такси/фактури/ledger),
потребителски изглед (акаунти) и платформен поръчков изглед.

## Решение

Разширяваме `/admin` от една страница в **5-табов команден център** (същият `Tabs` примитив +
`?tab=` URL като dashboard-а). Текущото съдържание се разпределя; добавяме 3 нови таба. Всичко
**read-only наблюдение** освен вече съществуващите действия (блокиране на магазин, inv.bg retry/annul).
Гард: `requireAdmin` (имейл в `PLATFORM_ADMIN_EMAILS`, иначе `notFound()`).

### Таб 1 — „Общ преглед"
- Съществуващите 5 метрики карти (магазини/публикувани/поръчки/оборот/търговци).
- + монетизационни акценти: общо начислени такси, неплатени фактури (брой + сума), кредити.
- + проблемни inv.bg фактури (вече ги има) с retry/annul.

### Таб 2 — „Магазини"
- Текущият списък + търсене/филтри по статус + действия (скрий/блокирай). Премества се непроменен тук.

### Таб 3 — „Монетизация" (ново)
- Метрики: общо начислени такси, платени/неплатени фактури, кредити (връщания).
- **Месечни фактури** (`fee_invoices`): период, търговец, `amountDueCents`, `invBgStatus`, Stripe статус —
  неплатени/проблемни първо.
- **Fee ledger** (`fee_events`): последни N начисления/кредити (тип charge/credit, магазин, `amountCents`,
  `baseCents`, дата). Read-only.

### Таб 4 — „Потребители" (ново, read-only)
- Списък акаунти: от Supabase `auth.admin.listUsers` (имейл, потвърден, последен вход, provider, регистриран)
  join с `profiles` (роля, име) + брой магазини (`shops` по owner).
- Търсене по имейл (клиентско филтриране на заредената страница; пагинация през listUsers page).
- Само наблюдение — без действия (изтриване/ресет са извън обхвата, добавят се по-късно ако потрябва).

### Таб 5 — „Поръчки" (ново, read-only)
- Последни поръчки през ЦЯЛАТА платформа (не по магазин): номер, магазин, `totalCents`, статус,
  плащане, дата. Филтър по статус. Пагинация.

## Архитектура

### Данни / queries (`src/db/queries/admin.ts` — разширяваме)
- `getMonetizationStats(): { totalChargedCents, unpaidInvoices: {count, cents}, creditsCents }`.
- `getFeeInvoicesList({page, status?}): { items, total, page, pageSize }` — от `fee_invoices` join `shops`.
- `getFeeLedger(limit): FeeEventRow[]` — последни `fee_events` join `shops`.
- `getPlatformOrders({page, status?}): { items, total, page, pageSize }` — `orders` join `shops`.
- Потребители: НЕ през Drizzle (auth.users не е в схемата) → `getAdminUsers(page)` в нов
  `src/db/queries/admin-users.ts` или направо в page чрез `createSupabaseAdmin().auth.admin.listUsers`
  + `db` за profiles/shops брой. Изборът: отделен сървърен helper `getAdminUsers` (server-only).

### Страница (`src/app/admin/page.tsx` — рефакторинг)
- Обвива всичко в `<Tabs>` с `?tab=` (overview|shops|monetization|users|orders).
- Всеки таб = `<TabPanel>` с проста read-only таблица (`Table/TBody/TCell/TH/THead/TRow` от ui).
- Данните се зареждат в page (Server Component) само за активния таб (или всички — малък обем,
  като dashboard-а). Реши: зареди всичко в `Promise.all` (просто, обемът е малък за 1 админ).

### Компоненти (нови, read-only композиции)
- `admin-monetization.tsx`, `admin-users-table.tsx`, `admin-orders-table.tsx` — само презентация
  (props → таблица). Съществуващите `admin-shop-actions`/`admin-invoice-actions` остават.

## Сигурност
- `requireAdmin` на страницата (вече има). Всички нови queries се викат само след него.
- Потребителският списък минава през `createSupabaseAdmin` (SUPABASE_SECRET_KEY, server-only) — никога NEXT_PUBLIC.
- Read-only — никакви нови мутации. PII на потребителите се вижда само от админ (законно — оператор).

## Тестване
- Unit: новите чисти query-трансформации ако има (напр. агрегиране на монетизация) — леко, повечето са SQL.
- Ръчно/Playwright: вход като админ → всеки таб зарежда + показва данни; не-админ → 404.

## Извън обхвата (YAGNI)
- Действия върху потребители (изтриване/ресет парола/потвърждаване) — само наблюдение сега.
- Графики/тренд диаграми — таблици стигат за старта.
- Импорт/експорт на админ данни.
